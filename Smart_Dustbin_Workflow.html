1   Project Overview

💡 The Idea

When someone throws trash toward an open dustbin, the bin automatically predicts where the trash will land and drives itself to catch it mid-air — so the garbage never hits the ground.

How It Works (In Plain English)

  1. A person throws a piece of trash toward the bin.
  2. The bin's camera sees the object flying through the air.
  3. The brain fits a curve — using physics (projectile motion), it predicts exactly where the trash will land.
  4. The bin drives to that spot at top speed (like an omni-wheel robot).
  5. Catch! The trash falls neatly into the open top of the bin.

2   Core Algorithm — How Prediction Works

Step 1: Observe the Flying Object

The camera captures the trash position every 16 ms. Each reading has small noise (±2 cm) and a delay (50 ms). We collect at least 5 observations before predicting.

Step 2: Fit a Projectile Curve

A thrown object follows projectile motion. We separate the 3 axes:

Horizontal:   x(t) = x₀ + vₓ · t    |    y(t) = y₀ + vᵧ · t

Vertical:   z(t) = z₀ + v_z · t − ½ g t²

We use least-squares line fitting on the observations. For the vertical axis, we first remove gravity (add ½gt² to each measured z), turning it into a straight line, then fit.

Step 3: Predict the Landing Point

We solve for the time t_hit when the trash falls back to the rim height (0.6 m):

z₀ + v_z · t − ½ g t² = rim_height

t_hit = (v_z + √(v_z² − 2g · (rim_height − z₀))) / g

Then the landing spot is simply: (x₀ + vₓ · t_hit,   y₀ + vᵧ · t_hit)

Step 4: Drive the Bin There

The bin moves with acceleration and speed limits (like a real robot with motors):

Motion Parameters

ParameterValueMeaning
V_MAX3.0 m/sMaximum bin speed
A_MAX5.0 m/s²Maximum acceleration
NOISE0.02 mCamera measurement noise (±2 cm)
LATENCY0.05 sDetection processing delay

The mover slows down near the target using: speed = min(V_MAX, √(2 · A_MAX · distance))

What Each File Does

smart_bin.wbt — The World

Defines the 3D environment: an 8×8 m arena floor, the bin (a blue open-top box made of 4 walls + a base, 0.56 m wide, 0.6 m tall), and a red trash ball (sphere, r=5 cm). Also contains a invisible "thrower" robot that acts as the supervisor.

bin_controller.py — The Brain

Runs every 16 ms. Reads the trash position → adds noise + delay → fits the projectile curve → predicts landing point → drives the bin there using speed/acceleration-limited velocity commands. Has a USE_BRAIN switch: True = predict & catch, False = stay still (baseline).

thrower.py — The Throw Machine

A supervisor controller that automates experiments. It spawns the trash at a "person's hand" position (−3, 0, 1.4 m), gives it a random velocity aimed to land 0–2 m from the bin, then checks if the bin caught it. Logs every throw to a CSV file. Runs 50 throws per session.

CSV Result Files

Each row = one throw. Columns: throw number, offset distance, intended landing point, bin position, how far the bin moved, whether it caught the trash (rim rule + physical check). Used to compute catch rates and generate graphs.

world_x = (pixel_x − cx) · depth / fx    |    world_y = (pixel_y − cy) · depth / fy

How to Run an Experiment

  1. Change the parameter in bin_controller.py (e.g., set NOISE = 0.05).
  2. Change OUT_NAME in thrower.py to a descriptive filename.
  3. Run the Webots simulation. Wait for 50 throws to complete.
  4. Open the CSV in Python/Excel and compute the catch rate.
  5. Repeat for each parameter value.

7   Key Technical Lessons

⚠️ Don't Read Physics Velocity for Control

In Webots, node.getVelocity() returns the velocity after the physics engine applies friction, gravity, and collisions. If you use this as "current velocity" in your acceleration limiter, floor friction will zero it out every step, and the bin can never accelerate. Track your commanded velocity internally in a Python variable.

💡 The Two-Step Launch

To spawn a moving object in Webots: Step 1 — set translation + resetPhysics(). Step 2 (next timestep) — call setVelocity(). If you do both in the same step, resetPhysics zeroes the velocity you just set.

💡 Removing Gravity for Line Fitting

The z-axis follows a parabola, not a line. Trick: add ½gt² to each observed z value. This cancels gravity, turning the curve into a straight line. Now standard linear regression works for all 3 axes.

💡 Saving Webots Worlds

If you save the world while the simulation is running, Webots saves the current positions and velocities — not the original values. Always reset the simulation (Ctrl+Shift+T) before saving, or have your controller reset positions on startup.
